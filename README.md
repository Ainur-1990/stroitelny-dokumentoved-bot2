# Строительный Документовед — Telegram-бот

Русскоязычный Telegram-бот для строительной компании: принимает документы и сообщения, запускает реальный ИИ-анализ, формирует структурированные черновики проверок и квалифицирует входящие заявки в карточки для менеджера.

## Что реализовано

- `/start`, `/help`, `/status`, `/plans`, `/leads` и меню кнопок.
- **Реальный анализ документов**: PDF и DOCX разбираются locally (pypdf / python-docx), фото документов уходят в vision-модель. Ответ — структурированный черновик: тип документа, ключевые данные, чего не хватает, вопросы, что делать дальше.
- **Два источника ИИ**:
  - серверный ключ сервиса (`AI_*` в окружении, обычно OpenAI-compatible шлюз) — работает для всех пользователей по умолчанию;
  - личный ключ пользователя (BYOK) — `/connect_ai`; обработки на своём ключе не расходуют лимит тарифа.
- **Карточки заявок**: сообщение клиента разбирается в структурированную карточку (объект, площадь, работы, бюджет, сроки, контакт), сохраняется в БД, администраторам приходит уведомление, `/leads` показывает последние заявки.
- Честные ограничения: бот готовит черновики, не подписывает документы, не даёт юридических заключений и не выдумывает цены, объёмы и нормативы.
- Webhook endpoint с проверкой секретного заголовка Telegram; ошибки обработчиков логируются, но webhook всегда отвечает 200 (без ретраев Telegram).
- Оплата цифрового доступа Telegram Stars: тарифы, pre-checkout, успешный платёж, защита от повторной выдачи доступа при редоставлении `successful_payment`, срок и лимиты обработок с учётом истечения тарифа.
- BYOK: одноразовая HTTPS-ссылка на 15 минут, ключ хранится только зашифрованным (Fernet), endpoint проходит проверку на публичный HTTPS (защита от SSRF через localhost/приватные сети).
- Dockerfile, `render.yaml`, `.env.example`, смоук-тесты (`python tests/smoke.py`, без сети).
- Пакет рекламных материалов Reels: `marketing/reels-scripts.md`.

## Что осталось за рамками MVP

RAG по СНиП/СП/ГОСТ, генерация DOCX/XML КС-2/КС-3, интеграции с CRM/ЭДО. С текущей архитектурой (extract.py + ai.py) эти шаги добавляются как отдельные модули без переделки бота.

## Тарифы и платежи

Цифровой доступ внутри Telegram продаётся за Telegram Stars: **Старт — 99 ⭐ / 10 обработок**, **Прораб — 299 ⭐ / 50 обработок**, **Компания — 799 ⭐ / 200 обработок**, каждый на 30 дней. Лимит расходуется только на серверном ключе; на личном ключе пользователя обработки не тарифицируются. Подробнее — в [PAYMENTS.md](PAYMENTS.md). ЮKassa оставлена для отдельного сценария оплаты внешних услуг.

## Быстрый запуск локально

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # Windows; на linux: .venv/bin/pip
cp .env.example .env
# заполните TELEGRAM_BOT_TOKEN и WEBHOOK_SECRET
# для локального теста анализа задайте AI_* (или подключите свой ключ через /connect_ai при публичном HTTPS)
.venv/Scripts/python tests/smoke.py             # 32 проверки без сети
POLLING_MODE=true .venv/Scripts/python app.py
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из @BotFather (обязателен) |
| `WEBHOOK_SECRET` | секрет для заголовка webhook и `/setup-webhook` |
| `PUBLIC_BASE_URL` | HTTPS-адрес сервиса (для webhook и ссылок BYOK) |
| `BYOK_ENCRYPTION_KEY` | Fernet-ключ для шифрования личных ключей пользователей |
| `ADMIN_USER_IDS` | Telegram ID администраторов через запятую: уведомления о заявках, `/leads` |
| `AI_PROVIDER` / `AI_MODEL` / `AI_ENDPOINT` / `AI_API_KEY` | серверный ИИ: `openai`, `anthropic`, `google` или `openai_compatible` (шлюзы) |
| `POLLING_MODE`, `PORT`, `LOG_LEVEL`, `DB_PATH` | режим запуска и служебные настройки |

## Постоянный запуск

GitHub хранит исходный код, но не является сервером для Telegram webhook. Для работы 24/7:

1. Создайте Web Service на Render из этого репозитория (или другой хостинг с HTTPS).
2. Добавьте секреты из таблицы выше.
3. После запуска вызовите:

```bash
curl -X POST "$PUBLIC_BASE_URL/setup-webhook" -H "X-Setup-Secret: $WEBHOOK_SECRET"
```

В `PUBLIC_BASE_URL` — адрес без завершающего `/`.

## Подключение личного ИИ-ключа (BYOK)

Пользователь запускает `/connect_ai`, получает одноразовую HTTPS-ссылку на 15 минут и вводит ключ на защищённой странице. Ключ не принимается обычным сообщением Telegram, не возвращается API и хранится зашифрованным. Поддержаны OpenAI, Anthropic, Google AI и OpenAI-compatible API (публичный HTTPS endpoint). Управление: `/ai_status`, `/disconnect_ai`.

`BYOK_ENCRYPTION_KEY` сгенерируйте локально: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` и вставьте только в переменные хостинга.

## Безопасность

- Токен бота не хранится в Git и не записывается в логи; в логи не попадают тексты сообщений, документы, API-ключи и платёжные данные.
- Webhook принимает обновления только с корректным секретным заголовком.
- BYOK-endpoint'ы проходят проверку: только публичный HTTPS, localhost и приватные адреса отклоняются.
- Не отправляйте в чат документы с персональными данными без утверждённых политик доступа и хранения.
- Перед отправкой заказчику специалист проверяет все черновики.
- Если токен попал в открытый доступ — немедленно перевыпустите его через @BotFather.

## Структура

```text
app.py                 # webhook/polling приложение, диалоги, тарифы, заявки
ai.py                  # адаптеры ИИ-провайдеров (openai/anthropic/google/compatible, vision)
extract.py             # извлечение текста из PDF и DOCX
byok.py                # шифрованное хранилище личных ключей и одноразовые ссылки
tests/smoke.py         # смоук-тесты без сети
requirements.txt       # зависимости

render.yaml            # шаблон Render
.env.example           # список переменных без секретов
marketing/             # сценарии рекламных Reels
```
